MEASURED (PROJECT.md, "Resolved since initialization"): Solidity `try`/`catch` DOES catch a
cheatcode-originated revert on 1.5.1. The low-level `address(vm).call` form ALSO works and remains
the conservative default, because it assumes nothing about codesize behaviour surviving a Foundry
bump. Use the low-level form.

MEASURED (PITFALLS.md:103): the `Vm` interface declares `rpc(...) returns (bytes memory)`, but the
raw returndata on 1.5.1 is `abi.encode(<coerced value>)`, NOT `abi.encode(<bytes>)`. A typed call
site therefore sometimes reverts with a bare `EvmError: Revert` and sometimes returns silent
garbage. This is why we take the returndata raw and decode it ourselves.

SOURCE (ARCHITECTURE.md:28): the 3-arg `vm.rpc` overload is `apply`, stateless — it needs no fork,
no anvil, and no `[rpc_endpoints]` entry.

Research probes ran against solc 0.8.34. Pin the same in the spike's foundry.toml so a different
solc cannot silently change the decode behaviour.

Phase 1 rule in force: EXIT CODE BEFORE GREPS.

<task type="checkpoint:decision" id="02-03-T1" gate="blocking">
  <name>Task 1: Why we hand-write the Vm interface and refuse the typed return</name>
  <read_first>
    - .planning/research/PITFALLS.md (section 100-115, Pitfall 3 — the typed call site's two failure modes)
    - .planning/phases/02-transport-spike-throwaway/02-CONTEXT.md (Specific Ideas — the four layers)
  </read_first>
  <teaching>
    Two decisions here, both counter-intuitive.

    **No forge-std.** The instinct is to inherit `forge-std/Test.sol` for `vm` and `assertEq`. We
    do not, for three reasons: it needs a submodule (deletion stops being `rm -rf spike/`), it
    brings a version we would then have to pin, and it gives us a TYPED `vm.rpc` — which is exactly
    the thing we must avoid. `require()` is a perfectly good assertion. `forge test` finds any
    contract with `test`-prefixed functions; the base class is a convenience, not a requirement.

    **The typed return is the trap, not the fix.** It is tempting to write:

        bytes memory b = vm.rpc(url, method, params);

    On 1.5.1 the raw returndata is `abi.encode(<coerced value>)` — the ABI encoding of whatever
    Foundry's `json_value_to_token` guessed, NOT the encoding of `bytes`. Solidity's decoder is then
    handed data that may not match `bytes`. PITFALLS.md:100-115 measured both outcomes: sometimes a
    bare `EvmError: Revert` with no message, and — worse — sometimes **silent garbage** that decodes
    without complaint.

    A silent wrong answer in an oracle is the failure this entire project exists to prevent. So we
    take the returndata RAW, record the bytes, and decode deliberately. The recorded bytes are the
    measurement; the decode is an interpretation of them, and interpretations get written down
    separately from observations.
  </teaching>
  <action>
    Walk the user through PITFALLS.md:100-115 together. Confirm they can state:
      - why `bytes memory b = vm.rpc(...)` is unsafe on the pinned version
      - why silent garbage is worse than a revert
      - why we record raw returndata before decoding anything
    Record the confirmation in 02-01-PROBE-NOTES.md.
  </action>
  <verify>
    # interactive: walk PITFALLS.md:100-115 with the user; no command output required
  </verify>
  <acceptance_criteria>
    - The user has confirmed the three points above
    - 02-01-PROBE-NOTES.md notes the decision to use the low-level form with a reference to
      PITFALLS.md:100-115
  </acceptance_criteria>
  <done>The user can state why the typed vm.rpc return is unsafe and why raw returndata is recorded before decoding.</done>

<task type="auto" id="02-03-T3">
  <name>Task 3: Write the test — low-level call, raw returndata, deliberate decode</name>
  <read_first>

    - .planning/research/PITFALLS.md (section 100-115)
  </read_first>
  <teaching>
    Structure the test so the OBSERVATION and the INTERPRETATION are separable:

      1. Build the calldata with `abi.encodeWithSignature("rpc(string,string,string)", ...)`.
      2. `(bool ok, bytes memory ret) = address(vm).call(cd);`
      3. `console`-log or emit `ret` verbatim, BEFORE touching it.
      4. `require(ok, ...)` — exit code before interpretation, the Solidity form of the Phase 1 rule.
      5. Only then attempt the decode.

    If step 4 fails, the errdata is a `CheatcodeError(string)` (`0xeeaa9e6f`) and the string body
    tells you what went wrong — connection refused, malformed body, timeout. Surface it rather than
    swallowing it: a failing spike must be diagnosable in one run.

    We do not yet know whether `abi.decode(ret, (bytes))` succeeds. That is the measurement. Write
    the decode so a failure is REPORTED, not so the test is shaped around an assumed answer.
  </teaching>
  <action>
    Write `spike/forge/test/Spike.t.sol`, pragma `0.8.34`:

    - Declare the interface minimally — do NOT import anything:

        interface VmLike {
            function rpc(string calldata, string calldata, string calldata) external returns (bytes memory);
        }
        address constant VM_ADDR = 0x7109709ECfa91a80626fF3989D68f67F5b1DD12D;

    - A contract `SpikeTest` with `function test_vmRpcReachesWarp() public`:
        - url `"http://127.0.0.1:8547"` (hardcoded; the env-var alias is SRV-09, Phase 6)
        - method `"spec_health"`, params `"[]"`
        - low-level `address(VM_ADDR).call(abi.encodeWithSignature("rpc(string,string,string)", url, method, params))`
        - emit an event carrying `ret` verbatim, and its `.length`, so `forge test -vvv` shows the
          raw bytes
        - `require(ok, "vm.rpc reverted -- see -vvv for CheatcodeError body")`
        - `require(ret.length > 0, "empty returndata")`
        - then attempt `abi.decode(ret, (bytes))` and emit the decoded value and its length
        - `require` the decoded bytes equal the stub's hardcoded 32-byte payload, using
          `keccak256(decoded) == keccak256(expected)`

    - Add a second function `test_rawShapeIsRecorded()` that performs the same call and emits ONLY
      the raw bytes with no decode and no equality assertion, so the shape is observable even if
      the decode assertion in the first test fails.

    Use `require` with descriptive messages throughout. No forge-std.

  <teaching>
    This is the most important task in the plan, and it is the one most likely to feel unnecessary.

    A test that passes is not evidence until you know it can fail. A `require` on a condition that
    is accidentally always true, a test function whose name does not start with `test` (so forge
    silently runs nothing and reports success), an assertion after an early return — all of these
    produce a green run that means nothing. Phase 1 hit this class NINE times.

    `forge test` reporting "0 tests passed" **exits 0**. A green terminal is not the same as a
    verified claim. Check the test COUNT, not just the exit status.
  </teaching>
  <action>

    2. Re-run `cd spike/forge && forge test -vvv` with NO server.

       `CheatcodeError(string)` (`0xeeaa9e6f`) and that its string body indicates a connection
       failure — this simultaneously re-confirms the measured `try`/`catch` finding on our own stack.
    4. Restart the server and re-run. Confirm green again.
    5. Separately, confirm the test count is non-zero in BOTH green runs — quote the
       "N tests passed" line. A run with zero tests is a false green.
