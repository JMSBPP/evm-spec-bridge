## Isolation

The spike carried its own `stack.yaml` and was not listed in the root one, so CI's `build` job never
compiled warp/wai or their transitive closure. The snapshot block was confirmed byte-identical to
the root's by `diff` (exit 0), and `extra-deps: []` — warp 3.4.9, wai, http-types, aeson,
bytestring and text are all in LTS 24.55, so the spike pinned nothing of its own. The files were
deliberately committed rather than gitignored, so that the eventual deletion would show as a
visible diff.

## Four properties, each with a reason — measured

| Property | Evidence |
|---|---|
| Even-nibble payload | generated by `printf '%064x' 42`, 64 hex chars, one 32-byte EVM word |
| Bound to loopback only | `ss -ltn` shows local bind `127.0.0.1:8547`; `curl` to the host's LAN IP is **refused, exit 7** |
| Port required, no default | `usage: stub-server PORT`, exit 1 |
| Request id echoed | sent `"id":7`, got `"id":7` back — the echo is real, not the fallback agreeing |

`curl` on localhost cannot distinguish a correct `127.0.0.1` bind from a wrong `0.0.0.0` bind — a
server bound to all interfaces answers that exact request identically. Hence `ss`, and hence the
LAN-refusal row. Three instruments, because the obvious one has a blind spot.

## Corrections to this plan's own claims

1. **The plan's payload literal was 62 characters, not 64.** The `<action>` block printed 60 zeros
   where `printf '%064x' 42` gives 62. The plan's own instruction — *"count it, do not assume"* —
   caught the plan's own error, and the correct value was committed. An odd-nibble payload would
   have left the bytes branch entirely and measured a different coercion branch, without
   necessarily turning the test red in an obvious way. **Write the invariant beside the value, not
   the value alone.**
2. **The isolation claim was 3/4 true.** `scripts/hpack-drift.sh` globs `*.cabal` **repo-wide**, so
   the spike's freshly generated `.cabal` turned the drift gate red until it was committed. Precise
   statement: the spike was invisible to `stack build`, to the seam guard's config, and to
   `.github/workflows/ci.yml` — but **visible to the drift gate**. Recorded rather than quietly
   corrected, because a claim that is 3/4 true is exactly the kind that gets remembered as 4/4.
   This is also why 02-05 had to check the drift gate *after* deletion, not merely that the tree
   was clean.
