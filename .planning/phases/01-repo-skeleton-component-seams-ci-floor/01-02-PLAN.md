<task type="checkpoint:decision" id="01-02-T1" gate="blocking">
  <name>Task 1: D2 — seven packages, or one package with internal-libraries?</name>
  <read_first>
    - .planning/phases/01-repo-skeleton-component-seams-ci-floor/01-RESEARCH.md (section "M5 — `internal-libraries` cannot express the seam", and the "Alternatives considered" table row "Seven packages | Two packages")
    - .planning/phases/01-repo-skeleton-component-seams-ci-floor/01-CONTEXT.md (section "Component structure")
  </read_first>
  <teaching>
    This is where the user learns what a Stack *package* actually is. Stack's `packages:` list
    selects at package granularity — a directory containing one `package.yaml` / `.cabal`. An
    internal library (`library foo` inside one `.cabal`) is not a package: its `build-depends` are
    carried by the *enclosing* package. So if `cfmm-adapter` were an internal library, the spec-less
    config would fail for the whole umbrella package, permanently, and could no longer distinguish
    "a core component gained the forbidden edge" from "the adapter has its legitimate edge". The
    guard would be red on every run and carry zero bits of information — the same defect as an
    alarm that is always sounding.
    The takeaway is transferable: **the granularity of your build units is the granularity of the
    invariants your build system can enforce for you.**
  </teaching>
  <decision>Seven separate packages, or fewer packages using `internal-libraries:`?</decision>
  <context>
    Seven packages costs seven near-empty `package.yaml`/`.cabal` pairs. The two-package alternative
    (core-with-internal-libs + adapter) *would* express the seam and halves the boilerplate — it is
    the strongest alternative and worth stating honestly. It is rejected because internal libraries
    are not addressable as build targets, so per-component `stack build` / `stack test` / per-component
    pedantic flags become impossible and the six-way graph the roadmap declares collapses into one
    stanza.
  </context>
  <options>
    <option id="seven-packages">
      <name>Seven packages (RESEARCH.md verdict — required, not preferred)</name>
      <pros>Expresses the seam with full information; each component is independently buildable and testable</pros>
      <cons>Seven near-empty package.yaml/.cabal pairs to maintain</cons>
    </option>
    <option id="internal-libs">
      <name>One package with internal-libraries</name>
      <pros>Far less boilerplate</pros>
      <cons>Ruled out by M5(a): enclosing package carries the dep, guard permanently red. Ruled out by M5(b): Stack 3.11.1 cannot target an internal library — `[S-8506] Stack failed to parse the target(s)`</cons>
    </option>
  </options>
