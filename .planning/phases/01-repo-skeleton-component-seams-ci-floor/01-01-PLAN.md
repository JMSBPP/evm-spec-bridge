  <teaching>
    `stack build --dry-run` proves a **build plan** exists. It does not prove a single module
    compiles. The research verified resolution and was explicit that compilation was NOT verified.

    now, in `/tmp`, means a failure costs a deleted directory instead of blocking six phases of work.
  </teaching>
  <action>
    Build a throwaway Stack project in `/tmp` whose only content is a dependency on the spec.
    Do NOT do this inside the repo — nothing here should be committed.

    ```bash
    SCRATCH=$(mktemp -d /tmp/specprobe.XXXXXX); echo "$SCRATCH"
    mkdir -p "$SCRATCH/src"
    cat > "$SCRATCH/stack.yaml" <<'YAML'
    snapshot:
      url: https://raw.githubusercontent.com/commercialhaskell/stackage-snapshots/master/lts/24/55.yaml
    packages:
    - .
    extra-deps:
    - git: https://github.com/JMSBPP/cfmm-vol-markets-spec.git
      commit: <SHA FROM TASK 2>
    YAML
    cat > "$SCRATCH/package.yaml" <<'YAML'
    name: specprobe
    version: 0.1.0.0
    dependencies:
    - base >= 4.7 && < 5
    - cfmm-vol-markets-spec
    library:
      source-dirs: src
    YAML
    printf 'module Probe (probe) where\n\nprobe :: Int\nprobe = 1\n' > "$SCRATCH/src/Probe.hs"

    # (a) plan only -- should be sub-second
    cd "$SCRATCH" && time stack build --dry-run

    # (b) THE REAL QUESTION -- a full compile of the spec and its Chart/cairo tree
    #
    # `set -o pipefail` is LOAD-BEARING. Without it, bash returns the exit status of the
    # LAST command in the pipeline -- `tee` -- which is 0 whether or not the build failed.
    # Verified: `( false 2>&1 | tee /tmp/x.log ); echo $?` prints 0.
    # `time` is inside the subshell so its `real` line reaches the log rather than the
    # outer shell's stderr.
    cd "$SCRATCH"
    ( set -o pipefail; { time stack build; } 2>&1 | tee /tmp/specprobe-build.log )
    PROBE_EXIT=$?
    echo "PROBE_EXIT=$PROBE_EXIT"
    ```
