  <teaching>
    A convention is a thing people intend to do. A mechanism is a thing the system will not let them
    fail to do. DIST-03 is currently a convention: the only thing stopping a `git push upstream
    develop:main` right now is remembering not to.

    Three settings turn it into a mechanism, and the third is the one people skip:
    - require a pull request before merging — no direct pushes
    - require the CI status check to pass — no merging a red branch
    - **`enforce_admins: true`** — the owner cannot bypass it either

    Without the third, protection applies to everyone except the one person most likely to be in a
    hurry at 2am. Self-binding is the whole point: the value of the constraint is precisely that it
    also binds the person who set it.

    Note the honest caveat from the research: the exact REST payload spelling for branch protection
    is fiddly (MEDIUM confidence), so apply it and then **read it back**. Do not trust that a
    request that returned 200 configured what you meant.
  </teaching>
