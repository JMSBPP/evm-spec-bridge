    Two things the user should be able to state after this task.

    **(1) The guard is `--dry-run`, and that is not a weakening — it is where the signal lives.**

    construction, not at compile time. So `--dry-run` gets 100% of the seam signal in 0.34 seconds,
    for zero compilation. Making the guard a real build would compile the whole core a second time
    under a different Stack install hash for exactly the same information. A guard that costs
    seconds runs on every push; a guard that costs twenty minutes gets skipped.

    would have been decorative.** Under the full config the spec IS in `extra-deps`, so Stack simply
    resolves the forbidden edge, reorders the build, and exits 0. The guard has to be a config in
    which the spec does not exist. This is why `stack-core.yaml` was chosen, and it is worth seeing
    both outputs side by side.

  <teaching>
    Committing a generated file looks like a smell until you see what it buys: a consumer can build
    the tree with plain `cabal` and no hpack installed. The cost is drift — the committed artifact
    can disagree with its source. Modern hpack removed the `-- hash:` line that used to make it
    refuse to overwrite hand edits, so the generated file is now *unconditionally* regenerated. That
    is what makes `git diff --exit-code` a trustworthy gate: the file cannot be defended by editing
    it, only by editing its source. This is the same gate shape the generated Solidity gets in
    Phase 8 — one habit, applied twice.
  </teaching>
  <action>
    Demonstrate M6 live before committing anything:

    ```bash
    echo "-- DRIFTMARKER" >> components/protocol/evm-spec-bridge-protocol.cabal
    grep -c DRIFTMARKER components/protocol/evm-spec-bridge-protocol.cabal   # 1
    stack build --dry-run >/dev/null
    grep -c DRIFTMARKER components/protocol/evm-spec-bridge-protocol.cabal   # 0 -- silently gone
    ```

    Point at line 1 of the regenerated file: it carries a version-stamped header
    (`-- This file has been generated from package.yaml by hpack version 0.39.6.`). That header is
    why the CI Stack version must be pinned — a different hpack writes a different first line and
