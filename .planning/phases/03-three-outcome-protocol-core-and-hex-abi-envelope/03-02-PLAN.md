would be vacuous once the type holds. So the deliverable is not a test that passes — it is a type
that makes the illegal program fail to compile, plus evidence that the failure was observed.

<verified_values>
**Component choice — DECIDED: `abi-codec`, not `protocol`.** 03-01-T3's acceptance criteria require
`Bridge/Protocol.hs` to import nothing from `Data.Aeson`. A `ToJSON` instance in `protocol` would
break that criterion directly. `abi-codec`'s stated purpose is already "Hex and ABI encoding for the
tagged result envelope" (`components/abi-codec/package.yaml`, `synopsis`). The wire rendering lives
where the wire encoding lives.

`components/abi-codec/package.yaml` currently has `dependencies: [base >= 4.7 && < 5]` and a
`library` stanza only — **no test stanza**. This plan adds `aeson`, `bytestring`, `text`, `base16-bytestring`.

`-Wmissing-export-lists` is ALREADY on for every component (`package.yaml` ghc-options). An explicit
export list is therefore mandatory, not optional — which is what makes "the constructor is not
exported" enforceable rather than a convention.

MEASURED, `PITFALLS.md:164`: a JSON `null` result comes back from `vm.rpc` as 32 zero bytes with
`success == true`. `PITFALLS.md:63`: a JSON number becomes `uint256`, or `int256` if negative — a
different ABI type from the `bytes` branch our envelope needs. `PITFALLS.md:82` is the rule this
type enforces: only a `0x`-prefixed **even-length** hex string has a total, value-independent
coercion.

`components/abi-codec/compile-fail/` is NOT a `source-dirs` entry, so hpack will not glob it into
the library and `stack build` will never try to compile it. Only `scripts/hex-only-guard.sh` does.
</verified_values>

  <name>Task 1: The abstract hex newtype with a single ToJSON</name>
  <read_first>
    - components/abi-codec/package.yaml (dependencies is `base` only; no test stanza yet)
    - components/protocol/src/Bridge/Protocol.hs (as written by 03-01 — the types this renders)

  </read_first>
  <teaching>
    There are two ways to keep a JSON number off the wire. One is to write an encoder that happens
    not to emit one, and a test that checks. The other is to make the field's type incapable of
    rendering anything else. Only the second survives the next person adding a field.

    The mechanism is ordinary Haskell: a `newtype` whose data constructor is left OUT of the module's
    export list. Outside the module, the only ways to obtain a value are the smart constructors this
    module exports, and every one of them produces bytes. There is no literal, no `Num` instance, no
    `fromInteger` — so `42` is not a well-typed expression at that position, and neither is `Null`.

    `Maybe` is banned here for the reason `PITFALLS.md:161-164` measured: `Maybe` collapses rejection
    into absence, aeson collapses absence into `null`, and Foundry collapses `null` into 32 zero
    bytes with `success == true`. Three lossy hops, no compile error at any of them. The three-outcome
    sum type from 03-01 is what replaces `Maybe`; this newtype is what stops the leak at the JSON layer.
  </teaching>
  <action>
    1. Add to `components/abi-codec/package.yaml` `dependencies`:
         - aeson
         - bytestring
         - text
         - base16-bytestring
         - evm-spec-bridge-protocol
       Do NOT add an `extra-deps` entry for any of them — all four are snapshot-resident in LTS 24.55.

    2. Create `components/abi-codec/src/Bridge/AbiCodec/Hex.hs` with this export list EXACTLY —
       note that `Hex0x` appears WITHOUT `(..)`:

         module Bridge.AbiCodec.Hex
           ( Hex0x
           , HexError(..)
           , hexOfBytes
           , hexOfText
           , hexText
           , hexBytes
           ) where

       Define:
         - `newtype Hex0x = Hex0x ByteString` — constructor NOT exported.
         - `hexOfBytes :: ByteString -> Hex0x` — total. Any ByteString has an even nibble count.
         - `hexOfText  :: Text -> Either HexError Hex0x` — the ONLY entry point from text. Rejects:
             * missing `0x` prefix            -> `MissingPrefix`
             * odd number of nibbles          -> `OddNibbleCount Int`  (carries the nibble count)
             * any non-`[0-9a-fA-F]` nibble   -> `NonHexNibble Char`
         - `hexText  :: Hex0x -> Text`       — renders `"0x" <> base16(bytes)`, lowercase.
         - `hexBytes :: Hex0x -> ByteString` — the decoded bytes, for the ABI layer.
         - `data HexError = MissingPrefix | OddNibbleCount Int | NonHexNibble Char`
           deriving `(Eq, Show)`.
         - `instance ToJSON Hex0x where toJSON = Data.Aeson.String . hexText`
           and `toEncoding = Data.Aeson.Encoding.text . hexText`. Define BOTH: aeson's default
           `toEncoding` routes through `toJSON`, but stating it removes the possibility of a later
           hand-written `toEncoding` disagreeing with `toJSON`.

    3. Do NOT derive `Num`, `Generic`, or anything with a `ToJSON` default. Do NOT write
       `deriving newtype (ToJSON)` — that would inherit `ByteString`'s instance, not ours.

    4. Rewrite `components/abi-codec/src/Bridge/AbiCodec.hs` to re-export `Bridge.AbiCodec.Hex`'s
       public surface, again WITHOUT `Hex0x(..)`.

    5. Regenerate and COMMIT `components/abi-codec/evm-spec-bridge-abi-codec.cabal` —
       `scripts/hpack-drift.sh` globs `*.cabal` repo-wide.
  </action>

<task type="auto" id="03-02-T2">
  <name>Task 2: scripts/hex-only-guard.sh — make the type fail in two distinguishable ways</name>
  <read_first>
    - scripts/seam-negative-test.sh (the CONTROL / NEGATIVE / CONTRAST pattern from 01-04)
    - scripts/hpack-drift.sh (script convention: `set -euo pipefail`, exit non-zero, name the offender)
  </read_first>
  <teaching>
    03-VALIDATION's "How the type-level claim is evidenced" puts a compile-fail check FIRST, ahead of
    citing the type definition, because only the compile-fail form proves the guarantee rather than
    restating it. A type you have merely read is a type you are trusting.

    Phase 1's rule applies unchanged: a guard nobody has seen fire is being trusted, and it must fail
    in **two distinguishable ways**, or "it fired" is indistinguishable from "it fires at anything".
    A compile-fail check that greps for "error" would go green on a typo in the snippet's import list.
    So each negative asserts a DIFFERENT, named GHC diagnostic, and the CONTROL stage proves the
    harness can produce a success at all.
  </teaching>
  <action>
    Create three snippets under `components/abi-codec/compile-fail/`:

      Control.hs        — imports Bridge.AbiCodec.Hex, calls `hexOfBytes (Data.ByteString.pack [0x01])`
                          and `Data.Aeson.encode` on the result. MUST COMPILE.
      RawConstructor.hs — same imports, writes `Hex0x (Data.ByteString.pack [0x01])`.
                          Expected diagnostic: `Data constructor not in scope: Hex0x`
      NumberBody.hs     — same imports, writes `Data.Aeson.encode (42 :: Int)` bound at type `Hex0x`
                          via `let h = 42 :: Hex0x`.
                          Expected diagnostic: `No instance for` ... `Num Hex0x`

    Create `scripts/hex-only-guard.sh`, `set -euo pipefail`, three stages, each capturing the exit
    code BEFORE any grep (Phase 2's `head` bug):

      compile() {  # $1 = snippet path; prints exit code, leaves output in $OUT
        OUT=$(stack ${STACK_FLAGS:-} ghc -- -fno-code -Wall \
                -package evm-spec-bridge-abi-codec -package aeson -package bytestring \
                "$1" 2>&1) ; echo $?
      }

      CONTROL  : compile Control.hs        -> exit MUST be 0.   If not, the harness is broken; abort
                                              with a message saying so, NOT with a pass.
      NEGATIVE : compile RawConstructor.hs -> exit MUST be non-zero
                                              AND "$OUT" must contain `not in scope: Hex0x`
      CONTRAST : compile NumberBody.hs     -> exit MUST be non-zero
                                              AND "$OUT" must contain `Num Hex0x`
                                              AND "$OUT" must NOT contain `not in scope: Hex0x`
                                              — this last check is what makes the two failures
                                              DISTINGUISHABLE rather than merely both red.

    Print `PASS: hex-only guard fired in two distinguishable ways` and exit 0 only if all three
    stages behaved. Exit 1 naming the stage otherwise.

    Run `stack build evm-spec-bridge-abi-codec` before the guard — `stack ghc` can only see the
    local package once it is registered. Put that as the first line of the script, not as a
    precondition a human has to remember.

    Add to `justfile`:

    A property test asserting "the encoder never emits `null`" would generate inputs, encode them,

    trivially-passing test is an artifact to remove, not reassurance to keep. `PITFALLS.md:171`

    supersession is recorded rather than left as a silent omission.
