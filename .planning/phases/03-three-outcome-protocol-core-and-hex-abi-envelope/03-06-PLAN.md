<verified_values>
**The six classes, and ONLY these six** (03-CONTEXT, "Boundary sweep scope"), hex encoding only:

| # | Class | Body |
|---|-------|------|
| 1 | zero | `abi.encode(uint256 0)` — 32 bytes of zeroes |
| 2 | above 2^64 | `abi.encode(uint256 18446744073709551616)` |
| 3 | negative | `abi.encode(int256 (-5))` |
| 4 | empty | zero-length body |
| 5 | 32-byte | a 32-byte payload, `0xcd` repeated |
| 6 | odd-nibble | **not a round-trip** — see below |

**Classes 1, 2, 3 are exactly the values `PITFALLS.md:63` and `:100-115` measured breaking the naive
path**: `"18446744073709551616"` coerced to `uint256` and `-5` to `int256`, both REVERTING the typed
`bytes memory b = vm.rpc(...)` form with no message. Inside our envelope they are body bytes, not
JSON values, so they must be inert. That is the claim being tested.

**Class 6 is the odd one and is deliberately not a round-trip.** `abi.encode` output is always a
multiple of 32 bytes, so our encoder CANNOT emit odd-nibble hex — 03-03-T2 asserts it and returns
`Left (OddNibbleEmitted n)` if it ever could. So class 6 tests the REFUSAL on both sides: the Haskell
`hexOfText` rejects odd input with `OddNibbleCount`, and no odd-nibble string is ever handed to forge.
`PITFALLS.md:78` is why it matters: odd-length hex is silently LEFT-PADDED with a zero nibble, so
`"0xabc"` becomes `0x0abc` — a different value, no error — and it falls off the bytes branch onto
the value-dependent string branch.

**EXPLICITLY OUT OF THIS PLAN** (03-CONTEXT, Deferred): **arrays**, and the **three-encoding
comparison** (hex / decimal string / raw number). Both belong to **Phase 8's coercion-conformance
fixture, criterion 4**. Arrays matter because on our untyped path a wrong-branch array decode
**cannot revert** — `int256[]` and `uint256[]` are byte-identical — so silence is the failure mode
and it stays unguarded until Phase 8. `gams-evm-transport` is owed those results measured on the
`vm.rpc` path; tell them when Phase 8 runs.

**Raw returndata for a hex-string result is `abi.encode(bytes)`** — 96 B for a 32-byte payload
(offset 32, length 32, data). **`convert_to_bytes` preserves TRUE length** — a 20-byte payload
returned length `0x14`, not padded (`FEATURES.md:27`, `02-01-PROBE-NOTES.md`).

Foundry pinned **v1.5.1 / `b0a9dd9`**; `./scripts/foundry-pin.sh` exits 0 before any run here.
`cast` ships with the same pinned binary, so the second keccak is version-scoped identically.
</verified_values>

<task type="auto" id="03-06-T2">
  <name>Task 2: BoundarySweep.t.sol — keccak two ways, lengths at every stage</name>
  <read_first>
    - solidity/src/SpecOracle.sol (callOracle, decodeEnvelope — 03-05-T2)
    - .planning/research/FEATURES.md line 27 (`convert_to_bytes` on the vm.rpc path only)
  </read_first>
  <teaching>
    Why keccak TWICE, from two places. The Solidity-side `keccak256(body)` is computed by the same
    process that did the decode; if the decode is wrong, the hash is a faithful hash of the wrong
    thing. `cast keccak` on the hex string the SERVER emitted is computed outside the EVM entirely,
    from the bytes we know we sent. Agreement between them means the bytes that entered forge are
    the bytes that came out. One hash on its own means only that the value is self-consistent.

    Why lengths at every stage. `convert_to_bytes` preserves TRUE length — a 20-byte payload came
    back as `0x14`, not padded to 32. That makes length a usable signal: if a body goes in at 32
    bytes and comes out at 96, or at 0, the coercion did something and the length is where it shows
    first. Record the number at each hop rather than only asserting the final equality, so a failure
    localises instead of just being red.
  </teaching>
  <action>
    Write `solidity/test/BoundarySweep.t.sol`, no forge-std. For each index `i` in `0..4`:

      (bool ok, bytes memory ret) = callOracle("spec_boundary", string.concat("[", vm_uint2str(i), "]"));
      require(ok, "transport");                                   // INTEG-05, unconditional
      // stage 1: raw returndata length
      uint256 lenRaw = ret.length;
      bytes memory payload = abi.decode(ret, (bytes));            // the abi.encode(bytes) wrapper
      uint256 lenPayload = payload.length;
      (uint16 v, uint8 tag, bytes memory body) = abi.decode(payload, (uint16, uint8, bytes));
      require(v == PROTOCOL_VERSION, "version");
      require(tag == TAG_SUCCESS, "tag");
      uint256 lenBody = body.length;
      bytes32 h = keccak256(body);
      emit BoundaryRow(i, lenRaw, lenPayload, lenBody, h);        // event, read from the trace

    and assert `h` against a hard-coded `bytes32` expectation per index. Also assert
    `lenPayload % 32 == 0` and `lenBody` equals the expected body length per index (32, 32, 32, 0, 32).

    params array — note in a comment that this is params construction, not payload parsing, and that
