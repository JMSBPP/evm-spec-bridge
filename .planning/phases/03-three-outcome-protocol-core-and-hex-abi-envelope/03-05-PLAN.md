    Criterion 1's operative clause is "**with no string matching on revert text anywhere in the
    path**". The reason is in Pitfall 1: the revert text is the ONLY thing that differs between a
    dead server and a JSON-RPC error, it is unstable English, and it is produced by Foundry, not by
    us. A test that matches on it is a test that a Foundry patch release can silently invert.

    So the discrimination has exactly two inputs, both of which we control:
      - `ok` from the low-level call — one bit, transport reached us or it did not
      - `tag` from inside the envelope — which outcome, when it did

    Both live in the success path. Nothing reads `ret` as text, ever.
  </teaching>
  <action>

    assertion helpers inline or use `require`. Three test functions:

      test_rejection_isReadAsRejection()

        require(ok, "transport");                       // fails the test unconditionally, INTEG-05

        require(v == PROTOCOL_VERSION, "version");
        require(tag == TAG_REJECTION, "tag");
        uint8 guardId = abi.decode(body, (uint8));
