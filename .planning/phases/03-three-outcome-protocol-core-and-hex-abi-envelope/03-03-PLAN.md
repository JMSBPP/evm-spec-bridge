<objective>
The hex-ABI envelope: `SpecOutcome -> "0x" <> hex(abi.encode(uint16 version, uint8 tag, bytes body))`,
and its inverse.

Purpose: PROTO-03. `PITFALLS.md:82` established that a `0x`-prefixed **even-length** hex string is
the only JSON shape whose `vm.rpc` coercion is total and value-independent. This plan makes the
bridge own that encoding instead of inferring it from Foundry's heuristics.

Output: `Bridge.AbiCodec.Envelope`, a tasty round-trip property, and ONE golden vector recorded
byte-for-byte for 03-05 and 03-06 to compare against.
</objective>

<verified_values>
**Layout — LOCKED by 03-CONTEXT, not re-derivable here:**
`abi.encode(uint16 protocolVersion, uint8 tag, bytes body)`. Version FIRST because it travels with
the bytes the Solidity test actually decodes; tag SECOND because ROADMAP criterion 1 says "reading a
tag byte" and this is the literal form; `bytes body` variable-length because Phase 2 MEASURED that
`convert_to_bytes` preserves TRUE length — a 20-byte payload came back as length `0x14`, not padded.

**Tag values — FIXED HERE (Claude's discretion per 03-CONTEXT "Claude's Discretion"):**

| Tag | Constructor | Body |
|-----|-------------|------|
| `0x01` | spec success | the domain payload's ABI encoding |
| `0x02` | spec rejection | `abi.encode(uint8 guardId)` |
| `0x03` | transport / protocol fault | `abi.encode(uint16 faultCode)` |

**`0x00` is deliberately NOT a valid tag.** `PITFALLS.md:164` MEASURED that a JSON `null` arrives as
32 zero bytes with `success == true`. If `0x00` meant anything, a null would decode as that meaning.
Reserving it makes the measured degenerate case an explicit decode failure.

**`protocolVersion = 1`** (`uint16`, wire `0x0001`), defined once in `Bridge.Protocol` by 03-01-T3.

**`web3-solidity-1.1.0.0`** is snapshot-resident in LTS 24.55, added to `protocol` in 03-01-T2.
Modules used: `Data.Solidity.Abi.Codec` (`encode`/`decode`), `Data.Solidity.Prim.Int` (`UIntN`),
`Data.Solidity.Prim.Bytes` (`Bytes`).

**It is a THIRD-PARTY encoder sitting between our types and the wire** (03-VALIDATION, "Known
Validation Gaps"). Its correctness is assumed here, not verified. If 03-06 finds a boundary class
that fails, `web3-solidity` is a suspect alongside our own code and the PROBE-NOTES entry must
record WHICH was at fault rather than assuming ours.
</verified_values>

<task type="auto" id="03-03-T2">
  <name>Task 2: encodeEnvelope — version first, tag second, even nibbles asserted</name>
  <read_first>
    - components/abi-codec/src/Bridge/AbiCodec/Hex.hs (hexOfBytes, hexText — 03-02)
    - .planning/research/PITFALLS.md lines 55-82 (the hex rule and the two hex traps)
  </read_first>
  <teaching>
    Why even-nibble matters, mechanically: on the `vm.rpc` path a `"0x…"` string is routed by LENGTH.
    An even-length hex string reaches the bytes branch (`address` at 20 bytes, `bytes32` at 32,
    `bytes` otherwise — all collapsed to `bytes` by `convert_to_bytes`). An ODD-length one does not
    parse as bytes at all, so it falls back to the value-dependent STRING branch — the branch
    `PITFALLS.md:63` measured changing type with magnitude. One stray nibble moves the payload onto
    the exact code path this envelope exists to escape. `PITFALLS.md:78` adds the second trap:
    odd-length hex is silently LEFT-PADDED with a zero nibble, so `"0xabc"` becomes `0x0abc` — a
    different value, with no error.

    Why the bridge owns the encoding rather than Foundry's heuristics: `vm.rpc` calls
    `json_value_to_token(&result, None)` with struct definitions DISABLED. There is no declared type
    anywhere on the path — as 03-CONTEXT puts it, "nothing on our path contradicts a type". The only
    way to get a stable ABI shape is to hand Foundry one shape it always coerces identically, and put
    all the structure INSIDE it.

    `abi.encode` output is always a multiple of 32 bytes, so the even-nibble property is a
    consequence of the layout — which is precisely why it must still be ASSERTED. A property that
    holds by accident of a library's behaviour is a property one library upgrade away from not
    holding, and `web3-solidity` is third-party code.
  </teaching>
  <action>
    Add to `components/abi-codec/package.yaml` dependencies: `web3-solidity`. No `extra-deps` entry.

    In `Bridge/AbiCodec/Envelope.hs` define:

      data EnvelopeError
        = OddNibbleEmitted Int      -- carries the emitted nibble count
        | UnknownTag Word8
        | ShortEnvelope Int
        | VersionMismatch Word16 Word16   -- expected, got
        | AbiDecodeFailed String
        deriving (Eq, Show)

      encodeEnvelope :: SpecOutcome ByteString -> Either EnvelopeError Hex0x

    Implementation:
      1. `body <- bodyOf outcome` — success: the payload bytes verbatim; rejection:
         `Data.Solidity.Abi.Codec.encode (fromIntegral (fromEnum guardId) :: UIntN 8)`;
         fault: `encode (faultCodeWord :: UIntN 16)`.
      2. `raw = Data.Solidity.Abi.Codec.encode (protocolVersion :: UIntN 16, tagOf o :: UIntN 8, body :: Bytes)`
         — a 3-tuple, so web3-solidity emits the head/tail layout Solidity's `abi.decode` expects.
      3. ASSERT `even (2 * ByteString.length raw)` — i.e. `ByteString.length raw` is what determines
         nibble parity; return `Left (OddNibbleEmitted n)` if it is ever odd. Also assert
         `ByteString.length raw `mod` 32 == 0` and return `OddNibbleEmitted` on failure, since a
         non-multiple-of-32 from a tuple encode means web3-solidity did something we did not model.
      4. `pure (hexOfBytes raw)`.

    Note in a comment that the assertion is expected never to fire against `web3-solidity-1.1.0.0`,
    and that if it EVER fires the library is the suspect, not the caller.

    Regenerate and COMMIT the `.cabal`.
